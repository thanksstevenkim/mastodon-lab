# Mastodon 4.6.2 Upgrade

## Upgrade date: 2026-06-25 21:03 KST

## Previous version: 4.5.11

## Target version: 4.6.2

## Downtime

Approximately 40-60 minutes

Reason:

- Multiple build failures during the upgrade
- Ruby runtime upgrade
- Database migration troubleshooting

## Backup performed: Auto-backup

## Update procedure:

1. git fetch upstream
2. git merge --no-ff v4.6.2
3. Resolve merge conflicts
4. bundle install
5. yarn install
6. git push
7. docker build -t mustardkim/mastodon-mustard:v4.6.2 .
8. docker build -f streaming/Dockerfile -t mustardkim/mastodon-mustard:v4.6.2-streaming .
9. docker tag mustardkim/mastodon-mustard:v4.6.2 mustardkim/mastodon-mustard:latest
10. docker push mustardkim/mastodon-mustard:v4.6.2
11. docker push mustardkim/mastodon-mustard:latest
12. docker push mustardkim/mastodon-mustard:v4.6.2-streaming
13. cd /opt/mastodon
14. sudo nano docker-compose.yml
15. Replace 4.5.11 into 4.6.2
16. docker compose pull
17. docker compose down && docker compose up -d

## Issues encountered

### 1. Yarn checksum mismatch

Symptoms:

- ajv checksum mismatch

Cause:

- Cached package checksum mismatch

Resolution:

```bash
YARN_CHECKSUM_BEHAVIOR=reset yarn install
```

This regenerated the cached checksums and allowed the installation to continue.

### 2. Ruby version mismatch

Symptoms:
Bundler::RubyVersionMismatch

Cause:
Project now requires Ruby 4.0.5.

Resolution:

- Installed Ruby 4.0.5 with rbenv.
- Reinstalled Bundler.
- Ran `bundle install` again.

### 3. Merge conflicts

Affected:

- backup_service.rb
- upload.tsx
- about/index.jsx

Cause:
Local modifications conflicted with upstream changes.

Resolution:

- Accepted the upstream implementation.
- Reapplied only the Mustard-specific customization afterwards.
- Avoid editing upstream files unless necessary.

### 4. Database migration

Symptoms

- `avatar_description` column missing
- `keypairs` table missing
- `require_2fa?` undefined method

Cause

Database schema was still at an older migration version.

Resolution

```bash
bundle exec rails db:migrate
```

Verified with:

```bash
bundle exec rails db:migrate:status
```

## Notes

- Major upgrade from 4.5.x to 4.6.x.
- Theme implementation changed and existing theme became incompatible.
- Ruby runtime upgrade required.
- Verify database migrations before starting production containers.

## Lessons learned

- Treat database migrations as part of the deployment, not a post-deployment task.
- Minimize local modifications to upstream files whenever possible.
- Record every issue encountered during major upgrades for future reference.
